# Logistics Analytics Initiative — Regional FMCG Distribution Network

**Author:** Satya Venkata Gokul G 
**Scenario:** A mid-size FMCG distributor operating three warehouses and ~250 retail outlets across the
Vijayawada–Amaravati corridor, Andhra Pradesh, facing inventory imbalance, inefficient last-mile
routing, and limited demand visibility.

This repository contains a 4-week logistics analytics project that progresses from strategic planning
through data cleaning, exploratory analysis, and finally predictive modeling and optimization. Each week
has a **written DOC report** and a matching **executable Jupyter notebook** — the notebooks are not
pseudocode; every table, statistic, and chart in the reports was generated by the code in the
corresponding notebook.

## Week-by-Week Summary

### Week 1 — Strategic Planning and Data Exploration
Defines the business scenario and five core KPIs (On-Time Delivery Rate, Inventory Turnover Ratio, Order
Fulfillment Cycle Time, Transportation Cost per Unit, Demand Forecast Accuracy). The notebook simulates a
3-year weekly order dataset (250 outlets, 40 SKUs) with realistic seasonality and festival demand spikes,
then runs KPI baselining, outlet clustering (K-Means), demand forecasting (Holt-Winters exponential
smoothing), and a capacitated vehicle routing prototype (Google OR-Tools).

### Week 2 — Data Collection, Cleaning, and Preprocessing
Simulates a deliberately messy raw order extract (duplicate rows, inconsistent identifier casing, missing
delivery/promised dates, invalid values, statistical outliers) and applies a full cleaning pipeline:
structural normalization and de-duplication, issue-specific missing-value handling (flag-vs-impute
depending on what the missingness means), IQR-based outlier flagging (retained for review, not deleted),
and feature standardization for downstream clustering. Concludes with validation asserts and an exported
clean dataset.

### Week 3 — Advanced Data Analysis and Visualization
Simulates a 6,000-shipment dataset (distance, shipment volume, delivery time, transportation cost,
transport mode) and produces eight purpose-built visualizations — each paired with a rationale for the
chart type and a written interpretation. Key finding: on-time delivery underperformance is concentrated
in specific zone × transport-mode combinations (South zone + Two-Wheeler is the worst performer, ~13%
on-time), not a uniform network-wide issue, and the shortfall is structural rather than seasonal.

### Week 4 — Predictive Modeling and Optimization
Trains and compares Linear Regression, Decision Tree, and Random Forest models to forecast delivery time,
with cross-validation, GridSearchCV hyperparameter tuning, and residual diagnostics. The tuned model's
predictions are then converted into on-time-delivery probabilities and fed into a PuLP linear program
that finds the cost-minimizing fleet-mix allocation per zone. The optimization mathematically confirms
that South zone's on-time ceiling (~56%) cannot be raised through fleet reallocation alone — a structural
network-design problem requiring a different class of fix (e.g., a satellite micro-hub), not a routing
tweak.

## Data Note

All datasets used across the four weeks are **synthetically simulated**, since the distributor's real
operational data was not available for integration. Each generator deliberately encodes realistic
operational relationships (seasonality, festival demand spikes, mode-dependent cost and speed, zone-based
distance profiles, and — in Week 2 — specific, realistic data-quality defects) rather than pure random
noise, so the analysis in every notebook is genuinely recovering a signal rather than fitting noise. The
same underlying scenario (zones, distances, cost structure) is reused across weeks for narrative
continuity, though each week's dataset is regenerated independently within its own notebook.

Every cleaning technique, EDA method, visualization, model, and optimization shown is written to be
**re-pointed at real operational data** with no structural changes once the distributor's actual
order-management, inventory, and GPS exports are available — only the data-loading cell would need to
change.

## Running the Notebooks

Each notebook is self-contained — it generates its own synthetic dataset at the top, so no external data
files are required. Open in Jupyter, JupyterLab, VS Code, or Google Colab and run all cells top to bottom:

```bash
jupyter notebook Week1_Strategic_Planning_and_Data_Exploration.ipynb
```

Notebooks are independent (each regenerates its own data), **except**:
- Week 2's cleaning pipeline outputs `orders_clean.csv` in the same schema Week 1 consumes, so Week 2's
  output can be substituted for Week 1's synthetic-clean generator once you want to chain them.
- Week 4 reuses Week 3's shipment-level dataset design (same feature set, extended with `day_of_week`)
  to keep the delivery-time prediction problem consistent with the Week 3 diagnostic findings.
